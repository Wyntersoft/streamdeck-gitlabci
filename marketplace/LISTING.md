## Description

Paste as-is. The first paragraph is plain text, as it's used for search results.

```
Watch your GitLab CI/CD pipelines and runners from Stream Deck. Branch keys show each project's latest pipeline in colour, name the job that's running, and let you retry a failed pipeline with a tap or cancel a running one with a hold.

Works with gitlab.com and self-hosted GitLab, on keys and on Stream Deck + dials.

BRANCH STATUS
• Green: passed. Yellow: passed with warnings. Red: failed.
• Cyan: building, with the running job and how many jobs are done.
• Purple: waiting for a runner, with how long it has been queued.
• Tap to retry failed jobs, hold to cancel. Both can be switched off per key.
• Watch one branch, or leave it blank to follow the latest pipeline on any branch.
• On a dial, turn to switch between branches or projects.

RUNNERS
• Runner Status keys show whether a runner is idle, paused or offline, or what it's building.
• Runner Health shows how many runners are online, how many are building, and how many jobs are queued.
• On a dial, Runner Health turns through every runner automatically.
• All runner keys update together, so they always agree.

SETUP
Create a GitLab personal access token with the api scope (read_api is enough to only view status) and paste it, with your GitLab URL, into any key's settings. The token is stored by Stream Deck on your computer and is only sent to your GitLab server.

Not affiliated with or endorsed by GitLab Inc.
```

## Privacy

```
Pipeline Status for GitLab connects only to the GitLab server you configure. Your access token and settings
are stored by the Stream Deck app on your computer and are sent only to that server, to read pipeline and
runner status and, when you ask, to retry or cancel pipelines. The plugin collects no analytics and sends
no data to Wyntersoft or anyone else.
```
